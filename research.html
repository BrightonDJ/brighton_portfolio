Industrial Research
Hybrid Object Detection for Aerial Imagery Aerospace & Defence · Individual

Research Question

Can a hybrid deep-learning approach improve detection of arbitrarily oriented objects in aerial imagery compared with existing oriented detection methods?

Motivation

Axis-aligned detectors under- or over-include background when objects appear at arbitrary angles — common in aerial and satellite imagery. Oriented detection recovers the true extent and heading of each object, which matters for downstream geo-intelligence tasks.

Methodology

Investigated and experimentally evaluated a hybrid object detection approach combining complementary representation-learning strategies for classification and localization.

Experiments

Trained and evaluated on a custom aerial imagery dataset spanning 18 object classes across 16K+ images, with comparative evaluation against existing oriented detection methods.

Evaluation

Mean average precision (mAP) on rotated-IoU matched detections, the standard metric for oriented object detection benchmarks.

Results

78%+ mAP on the custom dataset. Delivered two publishable research manuscripts as client technical deliverables.

Limitations

Performance degrades on densely packed small objects and under heavy sensor noise; angle boundary discontinuity (wraparound near 0°/180°) remains a general challenge in oriented detection.

Future Work

Exploring continuous angle representations to resolve boundary discontinuity, and evaluating transformer-based set-prediction approaches as a regression-free alternative.

Research Focus: Oriented Object Detection

Representative methods I've studied and analyzed in depth while working on aerial object detection research — the ideas below informed my analysis even where a given method wasn't used directly.

Representative Methods Analyzed
ReDetRotation-equivariant detector
Overview

Builds rotation equivariance directly into the backbone's convolutional filters, so features rotate consistently with the input rather than relying on data augmentation to approximate that behavior.

Mathematical Foundation

Uses group-equivariant convolutions over a discretized rotation group. For a rotation g and feature map f, an equivariant layer Φ satisfies:

Φ(g · f) = g · Φ(f)

Filters are defined over multiple orientation channels so the same learned kernel responds identically to a rotated version of its input — the network doesn't need to relearn a pattern at every angle.

Architecture

Rotation-equivariant backbone feeding a RoI-transform layer that aligns rotated features before a standard detection head.

Advantages

Fewer parameters needed to cover the same rotation range as augmentation-only training; more sample-efficient on limited aerial datasets.

Limitations

Discretizing the rotation group introduces quantization error at angles between sampled orientations; added compute cost from multi-orientation channels.

What I learned: equivariance is a structural property of the network, not a training-time trick — it holds even on unseen orientations.
Oriented R-CNN (ORCNN)Two-stage rotated detector
Rotated Box Parameterization

Extends the standard (x, y, w, h) box with an angle term θ:

box = (x, y, w, h, θ)
Angle Regression & Rotated IoU

The angle is regressed alongside box coordinates; overlap between predicted and ground-truth boxes is computed as rotated IoU rather than axis-aligned IoU, which correctly penalizes orientation error even when the axis-aligned extents match.

Geometric Optimization & Loss

Loss combines classification loss with a smooth-L1 (or similar) regression loss over the 5 box parameters, with careful handling near the angle boundary to avoid the discontinuity where θ wraps from 180° back to 0°.

What I learned: a lightweight midpoint offset representation for proposals keeps the two-stage pipeline efficient while still supporting arbitrary orientation.
Strip R-CNNDirection-aware feature extraction
Long Strip Convolutions

Uses elongated (strip-shaped) convolutional kernels instead of square ones, matching the typical aspect ratio of oriented objects like vehicles or runways rather than forcing a square receptive field to cover an elongated shape.

Direction-Aware Features & Context Aggregation

Strip kernels are applied along multiple directions, aggregating context along the likely long axis of the target — giving the network a head start on orientation before any explicit angle prediction happens.

Attention & Feature Interaction

Attention layers combine the directional strip features, letting the model weight which orientation's context is most informative for a given region.

What I learned: shaping the receptive field to match object geometry can reduce reliance on the detection head to recover orientation from scratch.
Spatial Transform Decoupling (STD)Studied method
Spatial Transformation & Coordinate Mapping

Applies a learned spatial transform to map features into a canonical (de-rotated) coordinate frame before further processing — conceptually related to a Spatial Transformer Network, but specialized for oriented-box prediction.

Decoupled Representation

Classification and localization are computed from separate transformed feature branches rather than one shared representation, since the two tasks benefit from different spatial invariances — classification wants rotation-invariant features, localization needs rotation-equivariant ones.

Localization, Classification & Attention

Each decoupled branch uses its own attention mechanism tuned to its task, then the outputs are recombined into a final oriented box and class prediction.

What I learned: decoupling classification and localization into separate spatial representations is a principled way to resolve a representational conflict between two tasks that want different invariances from the same features.
Oriented-DETRTransformer set-prediction detector
Transformer Encoder–Decoder

Treats detection as direct set prediction: a transformer encoder processes image features, and a decoder attends over a fixed set of learned object queries to predict boxes and classes — no anchors, no NMS.

Hungarian Matching & Set Prediction

Predicted boxes are matched to ground truth via bipartite (Hungarian) matching, minimizing total assignment cost:

minσ Σᵢ Cost(yᵢ, ŷσ(i))

This removes the need for hand-designed anchor boxes or post-hoc duplicate suppression.

Positional Encoding & Self-Attention

Since transformers have no inherent notion of spatial position, positional encodings inject location information into the features; self-attention lets every query attend to the full image context.

What I learned: extending DETR's set-prediction formulation to rotated boxes removes anchor-design choices entirely — an appealing direction for future detection heads.
Mathematical Concepts Explored

A mathematics-first look at the ideas underneath oriented detection and transformer architectures — the intuition and formulation behind each, not a full derivation.

Rotation Equivariance

Intuition: a function is rotation-equivariant if rotating the input rotates the output the same way, rather than the output changing unpredictably.

Φ(g·x) = g·Φ(x)

Application: rotation-equivariant backbones (ReDet) generalize across object orientations with fewer training examples.

Attention

Intuition: lets a model weigh how relevant every other position is to the current one, instead of only looking at a fixed local neighborhood.

Attn(Q,K,V) = softmax(QKᵀ/√d) V

Application: transformer detection heads (STD, Oriented-DETR) use attention to relate object parts across the whole image.

Transformer Mathematics

Intuition: combines self-attention with position-wise feed-forward layers, processing all tokens in parallel rather than sequentially.

z = LayerNorm(x + Attn(x)); out = LayerNorm(z + FFN(z))

Application: the encoder-decoder backbone of Oriented-DETR and the decoupled heads in STD.

Rotated Bounding Boxes

Intuition: extending an axis-aligned box with an angle parameter lets it hug an object's true orientation instead of its worst-case bounding rectangle.

box = (x, y, w, h, θ)

Application: core representation for ORCNN and every oriented-detection method on this page.

Optimization

Intuition: training adjusts model parameters to minimize a loss function via gradient descent, following the direction of steepest decrease.

θ ← θ − η ∇θ L(θ)

Application: every model here is trained by minimizing a combined classification + localization loss.

Hungarian Matching

Intuition: finds the lowest-cost one-to-one assignment between two sets — here, predicted boxes and ground-truth boxes — so each prediction is scored against exactly one target.

minσ Σᵢ Cost(yᵢ, ŷσ(i))

Application: Oriented-DETR's set-prediction training, replacing anchor matching and NMS.

Feature Fusion

Intuition: combines information from multiple feature branches or scales into one representation, since no single branch captures everything a detector needs.

f = α·f₁ + (1−α)·f₂   or   f = Concat(f₁, f₂)

Application: Strip R-CNN's directional feature aggregation; STD's recombination of decoupled branches.

Multi-Scale Learning

Intuition: objects appear at very different sizes in aerial imagery, so features are extracted and combined across multiple resolutions rather than one fixed scale.

Pl = Conv(Upsample(Pl+1) + Cl)

Application: feature pyramid-style backbones used in several of the detection architectures discussed here.

Loss Functions

Intuition: a single scalar that measures how wrong a prediction is, combining separate penalties for classification and box localization into one trainable objective.

L = Lcls + λ · Lbox

Application: joint training objective across ORCNN, STD, and Oriented-DETR.

Positional Encoding

Intuition: injects information about a token's position into its feature vector, since attention itself has no built-in sense of order or location.

PE(pos,2i) = sin(pos/10000^(2i/d))

Application: positional information is needed for transformer-based detection architectures to retain spatial relationships; Oriented-DETR incorporates positional information as part of its transformer formulation.

Geometric Transformations

Intuition: operations like rotation, scaling, and translation that map points from one coordinate frame to another while preserving (or predictably changing) structure.

x' = R(θ)·x + t

Application: STD's spatial transform layer; data augmentation for rotation-robust training.

Coordinate Systems

Intuition: choosing the right frame of reference (image, object-centric, or canonical/de-rotated) makes downstream computation simpler or more robust.

xcanonical = R(−θ)·(ximage − c)

Application: mapping oriented objects to a canonical frame before classification, as in STD.

Application Domain: Remote Sensing AI

Context

My computer vision research has primarily involved aerial and remote sensing imagery, where object scale, orientation, density, and image resolution introduce challenges that differ from conventional natural image detection — extreme scale variation, dense small objects, and domain-specific noise like cloud cover and sensor artifacts. Most of this work sits at the Centre for Airborne Systems (CABS) and in an aerospace & defence industrial research engagement.

Areas of work

  • Aerial imagery & satellite imagery analysis
  • Geo-intelligence — extracting structured signal from raw imagery
  • Image annotation & dataset engineering for remote sensing datasets
  • Object orientation estimation and image registration
  • Large image inference — tiling and stitching for high-resolution aerial frames
  • Geospatial analysis workflows

Pollen Grain Classification Published · CIS 2024

Problem

Manual pollen identification for palynology is slow and requires specialist expertise; automating classification from microscope imagery reduces that bottleneck.

Method

Adapted a LeNet-style convolutional neural network architecture for multi-class pollen grain classification.

CNN

TensorFlow/Keras implementation — convolutional feature extraction followed by fully connected classification layers.

Dataset

Curated and preprocessed a labeled pollen grain image dataset spanning multiple species classes.

Results

Achieved reliable multi-class classification accuracy, validated against held-out test data.

Hridhayakamalam — Graph-Based Pattern Generator Independent research

Graph Theory

Represents traditional South Indian Kolam patterns as graph structures, with vertices and edges encoding pattern connectivity.

Symmetry

Exploits rotational and reflective symmetry groups to generate consistent, aesthetically valid patterns from a small set of rules.

Bézier Curves

Uses Bézier curves to render smooth, curved connections between graph vertices rather than straight edges.

Mathematics & Algorithms

Combines combinatorics (pattern enumeration) with computational geometry (curve generation) into a customizable generator, entirely in Python.

Applications

Both a research exploration in graph-based generative design and a standalone artistic tool.

Petal Graphs — Symmetric Graph Generation Independent research

Geometry

Generates symmetric circular "petal" patterns from configurable width parameters.

Graph Construction

Plots vertices around a circular layout and connects them algorithmically based on symmetry rules.

Curves

Uses curved paths between vertices to form the petal shapes rather than straight-line connections.

Algorithms & Visualization

A configurable generation algorithm contributing to the broader Hridhayakamalam project framework.
